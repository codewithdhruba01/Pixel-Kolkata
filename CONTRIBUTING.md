# Contributing to Pixel Kolkata

Thank you for your interest in contributing!

## Ways to contribute

- Improve the map renderer or camera controls.
- Fix UI and accessibility issues.
- Add or improve pixel-art assets.
- Improve geographic data processing.
- Verify landmark metadata and attribution.
- Improve documentation and tests.

## Before starting

1. Read the project README and relevant documents in `docs/`.
2. Check existing issues and pull requests.
3. For large changes, open an issue to discuss the approach first.
4. Do not commit private API keys, service-role credentials or personal data.

## Development setup

```bash
git clone <repository-url>
cd pixel-kolkata
npm install
npm run dev
```

Use the scripts defined in `package.json` for linting, type checking and tests once configured.

## Branch and commit conventions

Use descriptive branch names:
- `feat/isometric-camera`
- `fix/chunk-loading`
- `docs/data-attribution`

Suggested commit prefixes:
- `feat:`
- `fix:`
- `docs:`
- `refactor:`
- `test:`
- `chore:`

## Pull request checklist

- [ ] The change has a clear description.
- [ ] Related issue is linked, if applicable.
- [ ] Type checking and linting pass.
- [ ] Tests are added or updated where appropriate.
- [ ] UI changes include screenshots or a short recording.
- [ ] New assets have documented authorship and licence.
- [ ] Geographic data changes include source and attribution details.
- [ ] No secrets or unrelated generated files are included.

## Geographic data and artwork

Only contribute data and artwork that you created or are permitted to redistribute. Include source, licence and attribution information. Do not trace or copy proprietary map artwork without permission.

## Code of conduct

Be respectful, constructive and welcoming. Focus feedback on the work, not the person. Harassment, discrimination and abusive behaviour are not acceptable.
